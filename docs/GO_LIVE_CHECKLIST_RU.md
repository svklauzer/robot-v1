## Этап 0 — почему нельзя идти в live прямо сейчас

Баг `#phantom-fill` книжил цену выхода по экономическому гейту
`MIN_PROTECTIVE_EXIT_PCT`, а не по рынку. Два крупнейших «выигрыша» истории
(TRX #272 +10.97, #281 +8.18) закрыты по `entry × 1.018` — выше максимума,
который сделка вообще видела. Честно те же сделки дают +3.92 вместо +19.15.

**Следствие для live:** такой ордер на бирже просто не исполнится. Система
рассчитывала PnL по цене, которую рынок не показывал, а на живых деньгах
получила бы рыночный филл — в 4–5 раз хуже. Все метрики, питавшиеся от
`closed_net_pnl`, завышены: validation gates, rolling PnL, capture rate,
exit-replay, метки `is_win` в ML-датасете.

**Что сделано:** филл ограничен рынком во всех 7 защитных ветках;
`validation_gates` считает `net_pnl_honest_usdt` и получил жёсткий гейт
`no_phantom_fills_in_sample`; `exit-replay` больше не сравнивает конфиг сам с
собой. Пока в окне валидации есть хоть один фантомный исход — live заблокирован
автоматически, вручную обходить не нужно.

## Этап 1 — набрать честную статистику (paper, 5–10 дней)

Критерии перехода дальше (все одновременно, по `GET /system/validation-gates`):

- [ ] `phantom_fill_count = 0` — старые исходы выкатились из окна
- [ ] `net_pnl_honest_usdt > 0` на окне ≥ 50 закрытий
- [ ] `positive_then_negative_rate_pct < 25`
- [ ] `closed_count >= VALIDATION_MIN_CLOSED_SIGNALS`
- [ ] `failed_setup_share_pct` ниже порога
- [ ] в ленте видны закрытия `trend_capture_band` — новый ярус фиксации работает
- [ ] `GET /ml/exit-replay` перечитан заново (`phantom_fill_trades = 0`)

Ожидание по калибровке (16 реальных траекторий 264–282, боевой
`ExitPolicyService`): **−10.05 → −2.60 USDT, +7.45**. Это всё ещё минус —
система не доказала edge, она лишь перестала врать о нём. Live открывается по
факту положительного honest PnL, а не по ожиданию.

## Этап 3 — live_limited (микро-размер, 1–2 недели)

Только когда `validation_gates.ready = true`.

```env
TRADING_MODE=live_limited
ROBOT_MODE=live
ENABLE_LIVE_ORDERS=true
LIVE_EXECUTION_MODE=live
LIVE_SIZE_FROM_BALANCE=true
```

- [ ] **Кэп нотионала согласован с размером позиции.** Дефолт
      `LIVE_MAX_ORDER_NOTIONAL_USDT=25` против типового нотионала
      `RISK_EQUITY_USDT × MAX_POSITION_MARGIN_PCT ≈ 124` — каждый ордер был бы
      отклонён в первый же день. Теперь это ловит `production_blockers`
      (#live-notional-trap). Выбрать одно: поднять кэп до ~150 **или** снизить
      `MAX_POSITION_MARGIN_PCT` на этап ramp-up.
- [ ] `MAX_TRADES_PER_DAY=12` активен (новый предохранитель от чурна: дневной
      лимит убытка не ловит серию мелких перезаходов, выедающих депозит
      комиссиями)
- [ ] `MAX_DAILY_LOSS_PCT` проверен, circuit breaker останавливает бота
- [ ] kill switch протестирован: `POST /live/kill-switch` + встроенный smoke
- [ ] плечо 1 (`LIVE_MAX_LEVERAGE > 1` требует `ENABLE_FUTURES=true` — проверяется
      блокером)
- [ ] `GET /system/readiness` без блокеров
- [ ] `POST /system/product-e2e-smoke` зелёный

## Что остаётся открытым (осознанный риск)

1. **Edge не доказан.** Даже после всех правок 16-сделочная выборка даёт −2.60.
   Улучшение +7.45 достоверно (знак сохраняется на всех подвыборках), но
   абсолютный результат отрицательный. Live — только после положительного
   honest PnL на живой выборке.
2. **Выборка мала.** 16 трендовых траекторий — не доказательство. Пороги
   `TREND_CAPTURE_*` и `MIN_PROTECTIVE_*` пересмотреть после ~50 закрытий.
3. **ML в shadow.** val AUC ~0.51 — монетка; метки до 25.07 испорчены фантомом.
   Переобучать только на исходах, закрытых после фикса.
4. **Издержки — структурный налог.** Round-trip 0.15% при медиане MFE 0.64%
   съедает четверть хода. Maker-вход лимиткой у края entry_zone (0.02% вместо
   0.05% + отсутствие слиппеджа входа) — самый крупный неиспользованный резерв.
5. **Grid и cross-arb** идут своими контурами и в этот чек-лист не входят;
   grid −4.15 на 146 циклах остаётся под наблюдением владельца.
