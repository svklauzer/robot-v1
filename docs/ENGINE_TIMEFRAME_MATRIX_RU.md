# Матрица движков: таймфреймы и уровни реакции

Дата: 2026-07-27. Отвечает на вопрос: «у нас стакан, объёмы, импульсы — надо
выбрать правильные ТФ, уровни реакции должны быть разные».

## Фактическое состояние (из кода, не из планов)

| движок | ТФ направления | ТФ входа | горизонт | профиль ведения |
|---|---|---|---|---|
| **SCALP** (micro_scalp) | 5m | 1m триггер, 1h только для HTF-вето | 5–45 мин | scalp |
| **RANGE** (range_strategy) | 1h коридор | 15m | до 90 мин | scalp |
| **TREND** (mtf) | 4h + 1h биас | 15m | часы | position |
| **CRT** | 4h (C1/C2) | 15m (`CRT_LTF_TF`) | часы | position |
| **GRID** | 1h (`GRID_TIMEFRAME`) | — (лестница лимиток) | до флипа режима | свой контур |

ТФ разведены корректно — движки не лезут за пределы своей полосы.

## Что было не так: уровни реакции

Depth-гейт имеет **7 параметров**. По профилю был разделён ровно **один** —
максимальный спред. OBI, стенка и CVD были общими: скальпер на 1m и трендовый
вход с 4h-биасом реагировали на стакан одинаково.

Это неверно по существу: **информативность мгновенного потока падает с ростом
горизонта сделки**. Для скальпа стакан — это и есть сигнал. Для позиции,
которую держат 5–12 часов, секундный перекос — шум.

## Разведённые уровни реакции

`services/depth_profiles.py` — единая точка, откуда пороги берут **оба** пути
входа (пред-проход и публикация). Раньше они читали настройки порознь — так
спред и развели, а про остальное забыли.

| параметр | SCALP | POSITION | смысл разницы |
|---|---|---|---|
| `max_spread_pct` | 0.08 | 0.12 | филл критичен только для скальпа |
| `obi_confirm` | 0.15 | 0.05 | позиции не нужен перекос «в свою сторону» |
| `wall_confirm` | 0.30 | 0.20 | стенка живёт минуты, а не часы |
| `obi_hard_veto` | 0.45 | **0.80** | режем только экстремум |
| `wall_rescue_max_adverse_obi` | 0.35 | 0.60 | |
| `cvd_block_ratio` | 0.35 | **0.70** | нужен явный поток против, а не колебание |
| `cvd_thin_ratio` | 0.9 | 1.0 | тонкая выборка режет лишь при 100% против |
| `cvd_thin_min_trades` | 1 | **3** | одна сделка — не выборка для часов |

Разделено **8 из 9** параметров (`cvd_min_trades` совпадает намеренно).

### Проверка на тех же восьми боевых случаях

| | было | стало |
|---|---|---|
| пропущено трендовых сетапов | **0 из 8** | **2 из 8** |

Прошли те, где перекос был умеренным (obi 0.514 и 0.527). Экстремальные
(0.87–0.89) по-прежнему режутся — **защита цела, убрана только
чувствительность к рядовым колебаниям**.

## Что осталось общим — и почему намеренно

- **`net_safe_pct`** (покрытие издержек) — физика комиссий одинакова для всех.
- **Хард-стоп и TP** — задаются структурой сетапа, а не профилем.
- **`cvd_min_trades`** — порог «выборка вообще состоялась», не профильный.

## Открытое: пороги подобраны рассуждением, не замером

Значения position-профиля выведены из логики горизонта и проверены на 8 боевых
случаях — это **не** статистическая калибровка. Для неё нужны исходы сделок,
прошедших с новыми порогами.

Что мерить через неделю: доля входов, прошедших depth-гейт по каждому профилю,
и их `net_pnl` в разрезе `profile`. Если пропущенные трендовые сетапы окажутся
систематически хуже — порог `obi_hard_veto` для position надо возвращать вниз.
Метрика для этого уже есть: `GET /analytics/depth-coverage`.
